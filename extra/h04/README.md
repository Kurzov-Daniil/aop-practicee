1. Навіщо в програмуванні окремий тип для «так» і «ні»?
   Щоб комп'ютер чітко розумів логіку (true/false) і приймав рішення у розгалуженнях (if/else), а не плутався з числами чи текстом.

2. Як сказати !(a && b) людською мовою?
   «Неправда, що виконані обидві умови одночасно» (або «хоча б одна з умов не виконується»).

3. Чим && відрізняється від &?
   && - це логічне «І» з лінивою перевіркою (якщо перше false, далі навіть не дивиться).

   & - це побітове «І» (або логічне без лінивої перевірки), яке обов'язково вираховує обидві сторони.

4. Чому програма не падає в if (x != null && x.name == "Іван"), хоча x порожній?
   Завдяки корокроткому замиканню (short-circuiting): перша умова x != null дає false, і далі x.name комп'ютер навіть не намагається читати.

5. Як запхати 32 відповіді «так/ні» в одне число?
   Використати 32-бітне ціле число (int), де кожен окремий біт (0 або 1) відповідає за одну відповідь «ні» чи «так».

6. Що швидше: n % 2 чи n & 1?
   n & 1 швидше на рівні процесора, бо це одна побітова операція, а % — це ділення, яке є важчим. Хоча сучасні компілятори зазвичай самі оптимізують n % 2 у n & 1.
